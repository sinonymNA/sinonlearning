# Arcade development notes

- Preserve the existing Next.js App Router, PostgreSQL helpers, Margins auth, and node-runtime room pattern used by `app/api/suspect/route.ts`.
- Prefer server-authoritative room state and polling when deployment does not provide durable WebSockets; never make local browser state the source of truth.
- Keep private game data out of public room state.
- Run `npm run build` after route or type changes.
- Continue toward the complete Classroom Arcade acceptance criteria; intermediate milestones are not final completion.

## Classroom Arcade architecture (read before editing `arcade-server/`)

- `arcade-server/` is plain ESM (no Next imports) so it is unit-testable with `node --test`. `room.mjs` = session lifecycle, host controls, normalised cumulative scoring; `games/*.mjs` = one authoritative class per game (`tick`, `act`, `view`, `points`); `api.mjs` = the single request handler used by the Next routes AND the tests; `bots.mjs` = developer-lab bots that act only through `room.act()`.
- Games read time only via `room.t()` (freezes while paused) and `room.dur(ms)` (test time scale). Never use `Date.now()` in a game.
- Views are the only thing clients see. Private data (imposter role/word, secret draw word, correct answer, hot-potato fuse) must never appear in a view for someone who should not have it. `arcade-server/tests/imposter.test.mjs` and `quickDraw.test.mjs` assert this; keep them green.
- Drawing: ONE protocol/validator (`drawing.mjs`) and ONE client engine (`components/arcade/DrawingCanvas.tsx`) shared by Quick Draw and Telephone.
- Rooms live in process memory (`lib/arcadeRuntime.ts`, same pattern as `/api/suspect`); coins/collections/content sets persist via `lib/arcadeDb.ts` (Postgres) or `MemoryStore` when `DATABASE_URL` is unset.
- Developer lab access: any signed-in teacher account (`isDeveloper` in `arcade-server/api.mjs`); guests and students are refused and each lab room is owned by its creator. `ARCADE_DEV_AUTH=1` (never honoured when NODE_ENV=production) enables a cookie identity for local browser/load tests.
- Accounts: `arcade-server/accounts.mjs` (username+password only, session token stored hashed, cookie `arcade_session`); never add email/real-name fields. Solo practice = `solo_create` in `api.mjs` (real engine + bots; `awardSolo` in `room.mjs`; per-day cap via `store.awardCapped`).
- Quick chat is PRESET PHRASES ONLY (`arcade-server/chat.mjs`). Never add free-text student-to-student messaging.
- Tests: `npm run arcade:test`. Load test (35 real HTTP clients): `npm run arcade:load -- --url http://localhost:3100`. Browser e2e: `node scripts/arcade-e2e.mjs`. Desktop fit check (page must never need vertical scrolling while playing): `node scripts/arcade-fit-check.mjs --size 1366x768 [--page projector]`; the fit layout lives in the `@media (min-width: 900px) and (min-height: 520px)` blocks of `app/arcade/arcade.css` (`.room-shell`, `.fit-body`, `.fit-main`).
- Two arcade modes: Party (original) and Abyss (`arcade-server/abyss.mjs`, `data/abyssPrompts.mjs`, `/arcade/abyss/*`, see `ARCADE_ABYSS.md`). Abyss pearls/fish are stored under the namespaced user id `abyss:<id>` and must never mix with Party coins/characters. The Abyss answer key (`tiers`) must never reach a client before the question is answered.
- Memory files to keep current after every milestone: `ARCADE_PLAN.md` (checklist), `ARCADE_PROGRESS.md`, `ARCADE_TESTS.md`. Do not tick a box unless it was verified.
- Retro Gridiron (`arcade-server/gridiron/`, `components/arcade/gridiron/`, `/arcade/gridiron`, see `ARCADE_GRIDIRON.md`): pure ESM engine (no DOM/Date.now/Math.random; all tunables in `config.mjs`), tests in `arcade-server/tests/gridiron.test.mjs`, browser smoke `scripts/gridiron-e2e.mjs`. The player only controls offence; CPU possessions are simulated in `opponent.mjs`. Keep rendering separate from logic and do not add backend state. Coach Career (`career.mjs`, `Career.tsx`) is a pure-ESM season/roster engine whose state is plain JSON in localStorage; it feeds ratings into `Game`/`PlaySim` via `roster`/`opp` options and must not add backend state either.
- Dacula Dash (`arcade-server/dacula/`, `arcade-server/games/daculaDash.mjs`, `components/arcade/games/DaculaDash.tsx`, see `ARCADE_DACULA.md`): board data is imported ONLY via `arcade-server/dacula/board.mjs`; never invent geography (the default board is a labelled hand trace, replace it with `scripts/dacula-geo-import.mjs`). Questions are original; teacher uploads go through `questionIO.mjs`. Dice, reachable squares, answers and wedges are decided server-side only.
- Pack Rush (`arcade-server/packs/`, `components/arcade/packs/`, `/arcade/packs`, see `ARCADE_PACKS.md`): pure-ESM engine (no Date.now/Math.random; time moves only through `advance(st, seconds)`, seeded RNG), JSON state in localStorage (`packrush:v2`), all tunables in `config.mjs`. The loop is shop -> table -> tap to tear open -> album/storage -> sell; keep it tactile (cards must be real card faces, never icons). Fake cash only, no real-money framing, no dark patterns, no gambling-style 50/50 packs; keep the Odds Lab. Run `node scripts/packs-econ.mjs` after any economy change and keep `npm run arcade:test` green.
- Hub (`arcade-server/hub.mjs`, `lib/arcadeHub.ts`, `components/arcade/hub/Hub.tsx`, see `ARCADE_HUB.md`): the home and Games pages are built from the `HUB_GAMES` catalog as mood shelves (max 3 cards per shelf, extras behind "See all") plus a Continue row. To add a game, add ONE catalog entry (mood + tagline of at most 5 words); never add a standalone card or tile. Hub pages are calm by default (`hb-calm`): no looping animations. `node scripts/hub-e2e.mjs` checks it in a browser.
- Meowdoku (`arcade-server/meowdoku/`, `components/arcade/meowdoku/`, `/arcade/meowdoku`, see `ARCADE_MEOWDOKU.md`): a candy-style world map (100 levels, 10 cat-themed areas in `areas.mjs`) leading into a pure-ESM puzzle engine. Levels are pre-built in `levels.mjs` (rebuild with `node scripts/meowdoku-build-levels.mjs` if the generator, hint techniques, difficulty ramp or `LEVEL_COUNT` change). Every puzzle must have exactly one solution and be solvable by the hint techniques up to its tier (levels 1-6 only ever need "one spot left"). Marks change only through `setCell` (tap/double-tap/swipe gestures are explicit; never reintroduce a tap-to-cycle); a swipe is one undo stroke. Stars/score/rewards are first-clear only (`completeLevel`). Keep it original (own cats, art and scenery); see the name/logo note in the doc. Modes live in `modes.mjs` (Daily, Endless, shop, Sweep, Sardine; dates and seeds are always passed in); every puzzle comes from `generateWith`. The app opens on a Home screen (`Home.tsx`) that must never scroll. Fake yarn only: no real money, no timers, no odds. `node scripts/meowdoku-e2e.mjs` checks it in a browser (a few minutes; use `--only name,name`). The arcade's pixel font is `PressStart` (not `Press Start 2P`).
- Shelf Stocker (`arcade-server/shelf/`, `components/arcade/shelf/`, `/arcade/shelf`, see `ARCADE_SHELF.md`): a sorting puzzle in nine departments (Clothing Corner, Book Nook, Boutique, Toy Aisle, Pantry, Shoe Wall, Gift Corner, Customer Orders, Mixed Day), one rule each, plus a Daily Delivery, coins and a cosmetic decor shop (fake coins only, no real money, no timers, no odds). Level picks come from `levels.mjs`, built by `node scripts/shelf-build-levels.mjs` (rebuild after any change to the generator, a rule or the curve). Feel and smoothness are the point: flat cached sprites moved by CSS transforms and Web Animations, particles created imperatively, never WebGL/three.js, per-frame React state or heavy filters. `whyNot` in the engine is the only legality check and the source of the refusal messages. The engine is pure ESM (no Date.now/Math.random), levels are seeded and proven solvable, state is plain JSON in localStorage (`shelfstocker:v1`). The page must never scroll; `node scripts/shelf-e2e.mjs` checks fit, the rules and frame times at six sizes. Original name/art only. A wrapped (mystery) item must never move with a run (`topRun` stops at it; the solver encodes wrapped items as key+32). The app opens on a Home screen that must never scroll; the animated `Scene` per department uses transform/opacity only. Class decks are still deferred. Sound lives in `audio.ts` (synthesized, honours the arcade mute); drag-to-move shares `tap`/`doMove` with tapping and must never bypass `whyNot`.
